Azure DevOps and SRE

GitHub Actions DevSecOps pipeline

A pull-request pipeline that checks code, dependencies, secrets and the container image before anything moves toward an environment.

What it shows

  • Five parallel quality and security jobs, then a container job that only runs if all five pass.
  • Container smoke test, non-root check, Trivy gate on fixable critical CVEs and an SBOM as a build artifact.
  • A manual promotion step into a protected environment, plus a written guide to OIDC login to Azure without stored secrets.
Tested
8 unit and HTTP tests pass locally. The workflow file is ready in the repository and runs on GitHub-hosted runners once enabled.
Limits
No registry push or real deployment; actions pinned to release tags rather than commit SHAs.
  • GitHub Actions
  • Python
  • Docker
  • Ruff
  • Bandit
  • Gitleaks
  • pip-audit
  • Trivy
  • CycloneDX

Azure Pipelines for a Transaction API

A multi-stage Azure Pipelines workflow for a fictional bank's transfer API, built around audit-friendly promotion.

What it shows

  • Pull-request checks: unit tests, syntax check and a quality-gate step.
  • One versioned package promoted Dev → UAT → Prod, with an approval and business-hours check before production.
  • A documented rollback to the last good package in under 15 minutes, and idempotent transfer logic.
Tested
Python unit tests and YAML parsing run in GitHub Actions on every push.
Limits
The pipeline YAML is validated for syntax, not run against a real Azure DevOps organisation.

Azure DevOps and SRE

SRE observability and incident management

SLO-based monitoring for a small service: alert on error-budget burn, route pages and tickets differently, and close the loop with a runbook and review.

What it shows

  • Recording rules and multi-window burn-rate alerts (14.4x over 1h and 5m, 6x over 6h and 30m) with promtool unit tests.
  • An error-budget calculator: on the synthetic incident it reports 47.4% of the budget used and a page at 34x burn.
  • A Grafana dashboard, two runbooks, a fictional RCA and a reusable RCA template.
Tested
11 Python tests pass locally. Rule tests use promtool in CI once the updated workflow is enabled.
Limits
Single service and SLI; synthetic traffic only; no long-term metrics storage.
  • Prometheus
  • Alertmanager
  • Grafana
  • Python
  • Docker Compose

Azure DevOps and SRE

AKS + Helm delivery with SRE practices

A containerised API packaged for AKS and delivered through a staged pipeline with an SLO and an incident runbook.

What it shows

  • Helm chart with liveness and readiness probes, non-root user, HPA and PodDisruptionBudget.
  • CI with unit tests, helm lint and image scan; staging deploy with helm upgrade --atomic; approval before production.
  • A 99.5% availability SLO over 28 days with burn-rate alerts and an on-call runbook.
Tested
helm lint, helm template, unit tests and a local smoke test of the API run in GitHub Actions.
Limits
Not deployed to a real AKS cluster; ingress and cluster provisioning are described, not built.

Windows Server and Linux administration

Windows and Linux server ops toolkit

Day-to-day fleet checks: health, patch status, Active Directory hygiene, SSH baseline and user audit.

What it shows

  • Read-only PowerShell reports with JSON/CSV output and 0/1/2 exit codes for monitoring.
  • Bash health check, SSH hardening check (first value wins, as in sshd) and user audit.
  • One state-changing script that only restarts allow-listed services and confirms each restart by default.
Tested
7 Bash tests against fixture files pass locally; Pester and ShellCheck run in CI once the updated workflow is enabled.
Limits
Calls that need a real Windows Server or Active Directory were not run; the SSH baseline is a short list, not a full benchmark.

Patching and OS upgrade lab

A safe patching routine for Windows and Linux: snapshot, patch, compare, report.

What it shows

  • Pre-checks that snapshot OS build, free space, services, ports and pending reboot.

Tested

Limits
Lab hosts are synthetic; Windows patching itself is described rather than scripted.

  • Bash

  • Python
